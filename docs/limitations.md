# Ограничения и что можно улучшить

## Token bucket никогда не забывает ключи

Ведро создаётся для каждого нового ключа и остаётся в `map` навсегда. Если ключ — IP-адрес, то за неделю работы там окажутся сотни тысяч вёдер, и память будет только расти. Нужна периодическая чистка: удалять вёдра, которые давно полные (клиент не приходил дольше, чем нужно на полное пополнение).

## Один mutex на все ключи

Все запросы, даже от разных клиентов, по очереди проходят через один `sync.Mutex`. На небольшой нагрузке это незаметно, но под тысячами запросов в секунду станет узким местом. Можно разбить `map` на несколько частей (шардов) со своим mutex у каждой.

## В Redis не всё атомарно

Добавление запроса и подсчёт выполняются атомарно, а удаление отклонённого запроса — уже отдельной командой. В короткий промежуток между ними другой запрос может увидеть «лишнюю» запись и тоже получить отказ, хотя лимит ещё не исчерпан. То есть под сильной конкуренцией лимитер может быть чуть строже, чем нужно (но никогда не пропустит больше лимита). Правильное решение — переписать всё в один Lua-скрипт, который Redis выполнит целиком без перерывов.

## Sliding window log тратит много памяти

Хранится каждый запрос. Для лимитов вроде «10 000 в час» лучше подходит sliding window counter: храним только два счётчика — для текущей и прошлой минуты — и считаем приблизительно. Немного неточно, зато константная память.

## Время берётся с сервера приложения

Score в Redis — это время на машине, где запущен сервис. Если на разных серверах часы расходятся на секунду, окно у них тоже немного разное. Можно брать время из самого Redis командой `TIME` (а в Lua-скрипте это и так было бы бесплатно).

## ByIP не учитывает прокси

`ByIP` берёт адрес из `RemoteAddr`. Если сервис стоит за nginx или балансировщиком, это будет адрес балансировщика, и все клиенты получат один общий лимит. Тогда нужно брать IP из `X-Forwarded-For`, но только если доверяешь прокси, иначе клиент подставит туда что угодно.

## Один лимит на весь сервис

Нельзя задать «на логин 5 в минуту, а на остальное 100». Сейчас это решается двумя разными лимитерами и двумя middleware. Можно было бы сделать правила по путям.
